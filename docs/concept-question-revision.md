# 1~3장 개념 종합 문제 개정 · 2026-10-21

`빅데이터1-3장.pdf`는 개념의 출처다. 출제 목표는 문서의 숫자·예시·구성을 기억하는지가 아니라, 그 개념을 설명하고 새로운 상황에 적용하는지다.

## 변경 내용

- 기존 5회 × 40문항, 총 200문항을 검토했다. 55개 질문의 조건·과제를 수정했다. 개념을 이미 직접 묻던 나머지 145개 질문은 유지했다.
- 문서의 행·열 수, 결측 건수, 등장 작품·감독, 예제 경로·함수, 장르 순위를 외워야 하는 문항을 교체했다.
- 계산에 필요한 전체 건수, 시간 단위, 부분 연도 관측 조건을 문항에 명시했다.
- 21문항에 코드 또는 표를 제공한다. 풀이 뒤 결과 화면과 오답노트에서도 같은 자료를 볼 수 있다.
- 200문항의 페이지 확인용 풀이 문구를 개념·조건·계산 근거로 바꿨다. 본문 설명과 같은 문장은 다시 나열하지 않는다. 출처 페이지는 해설 하단에 남겼다.
- 회차마다 1장 9·2장 13·3장 18문항을 섞는다. 중하 32·중 6·상 2, 정답 위치 각 10개를 유지한다. 난이도는 편집 목표이며 실측 정답률이 아니다.

|이전 질문의 문제|개정 후 평가하는 능력|
|---|---|
|고정본의 행·열 수 암기|`df.shape` 출력이 주어졌을 때 행·열 의미 해석|
|감독·출연진·국가 결측 건수 암기|결측표와 분석 목적에 맞춰 유효 관찰 대상 결정|
|상위 장르의 건수 암기|장르 집계표에서 보유량과 시청 선호를 구별|
|예제 함수의 출처 암기|import 코드를 읽고 새 환경에 필요한 모듈 판단|
|고정 작품의 감독 정보 암기|새 데이터의 비결측 건수 계산|
|연도별 등록 수 암기|주어진 표의 차이를 계산하고 해석 범위 제한|

문항별 검토 분류는 `concept-question-review.json`, 분포·참조 검사는 `final-scope-audit.json`에 기록한다. 원본 PDF나 추출 텍스트는 저장소에 추가하지 않았다.

## 접근과 기록 보존

- 왼쪽 **개념 종합 · 1~3장**에서 연습·모의고사 각 1~5회를 선택한다.
- 목록 주소: `#/cbt?scope=concept`, `#/mock?scope=concept`.
- 기존 `#/cbt/final-1` ~ `final-5`, `#/mock/final-1` ~ `final-5`는 개정판을 시작한다.
- PDF 4개 전체를 사용하는 `course-1` ~ `course-5` 회차는 계속 제공한다.
- 새 문항은 `F26R01Q01` ~ `F26R05Q40` ID를 쓴다. 이전 `F01Q01` ~ `F05Q40` 200문항의 내용·선지·정답은 보관한다.
- 새 회차·장별 연습에서는 개정 문항만 출제한다. 기존 초안·결과·오답·북마크·백업 복원에서는 당시 문항을 사용한다. 진행 중인 이전 회차를 이어 풀면 이전 문항이 보이는 것이 정상이다.

## 검증

- `python scripts/final_scope.py`: 재현 가능한 콘텐츠 생성.
- `npm run validate`: 200개 고유 질문, 출처 페이지, 세 장의 분포, 난이도, 정답 배치, 표의 열·행 일치 검증.
- `npm test`: 39개 테스트. 적체·속도비·결측률·유효 N·관계 수·비결측 건수·연도 차이 독립 계산, 이전 200문항의 내용 해시, 이전 응시·북마크의 백업 복원과 채점 포함.
- `npm run build`: 타입 검사 및 정적 빌드.
- 앱 내 브라우저: 기존 초안 재개, 개념 목록·회차 이동, 제공 코드·표, 오답 표시·해설, 모바일 가로 넘침 확인.
- GitHub Actions의 `test:final-browser`: 데스크톱에서 200문항 전체 응시, 모바일에서 회차별 8문항 응시, 실제 자료 표시·채점·재접속·결과 자료·이전 문항 재풀이 검증.
- 기존 전체 PDF 문제·필기노트·차트·내비게이션 브라우저 검사도 배포 전 실행한다. Actions 실행의 성공 여부가 배포 확인 기준이다.

자동 검사는 문서 암기를 요구하는 표현의 재발, 수치·참조·기록 호환성을 확인한다. 문제의 교육적 타당성이나 실제 시험 적중을 보증하지 않는다.
